# Design system

## Implemented today

Source: `src/app/globals.css`, `src/app/layout.tsx`, `src/components/*.tsx`. The visual direction is a white, light-only, restrained inbox utility with a lowercase `mable.` wordmark, indigo accent (`#2F39A9`), generous intro spacing, and a list of questions. Titles appear without eyebrow labels throughout the app, on the welcome page and in the signed-in view. There is no theme selector or dark theme implementation.

| Token/pattern | Actual value/use |
| --- | --- |
| Font | Inter loaded through `next/font/google` in the root layout and served by the app; shared `--font-sans` token covers body, native controls, and HeroUI/Tailwind. Body 14px. |
| `--ink` / `--muted` | `#142536` / `#718093` |
| `--line` / `--blue` / `--pale` | `#e7edf3` / `#2f39a9` / 10% accent mixed with white |
| Main shell | 860px max-width, centered, 34px desktop horizontal padding. |
| Headline | Welcome 42–66px with tight tracking; signed-in view has no intro headline. |
| Forms | 9px radius, 11px/12px padding, blue focus border and pale focus ring. |
| Dialog | 540px maximum width by default (run setup 420px, history 620px), 17px radius, overlay and scrollable panel. |
| Responsive rule | At max-width 600px, shell padding shrinks, action icons move below questions and menu stacks. |

The shared accent also drives HeroUI’s `--accent`, active switch-icon buttons, links, focus borders, and primary control text; pale surfaces and focus rings derive from it. Action-specific colors remain unchanged.

The signed-in questions view starts with a full-width rounded question input with a light-gray (`#f7f9fb`) background in both idle and focused states and a 1px `--line` border, changing to the blue accent on focus without a shadow. It is 64px tall on desktop and 48px on mobile (at the existing 600px breakpoint), with 16px horizontal padding, #212121 text, 600 weight, and responsive 18–24px type with no adjacent add button, without an intro heading, list heading, or empty-state card. Typing a nonblank question reveals four icon-only square action buttons below the input: Mark as read, Star, Archive, and Label. Action buttons emerge from behind the input one by one: each slides down and fades in over 620ms, staggered by 140ms in Mark as read/Star/Archive/Label order. The input layers above them to mask their origin. Clearing the input reverses the stagger (Label through Mark as read), sliding buttons back behind the input before unmounting. Controls are inert during exit, and typing again cancels it. Reduced-motion preferences skip visible movement. Multiple actions can be selected. Label expands horizontally from its square icon into a 280px purple surface over 620ms, revealing a searchable HeroUI ComboBox to the right of the icon with a fade/slide. The inner selector uses a 10px radius with a consistent 6px top, bottom, and right inset inside the 16px outer radius, on desktop and mobile. Closing reverses the expansion; the hidden selector is inert. The control wraps as a unit on narrow screens and is capped to the available width. Reduced-motion preferences skip the transition. Opening Label starts with no selected label and an empty search field; editing an existing rule preserves its saved label. It filters labels case-insensitively and shows a “Create label” option for nonblank searches with no matches; creating a label selects it immediately. There is no separate label-name input or persistent Create button. Once at least one action is configured (Label requires a selected Gmail label), the inline hint becomes a clickable “Save” in the ink color (`#142536`), retaining its size and weight. The hint morphs into Save with a reversible blur, scale, and opacity transition (380–480ms), anchored to the right; the hidden prompt is removed from layout sizing when Save is shown or Label is expanded, so Save stays alongside the action boxes. On narrow screens the actions wrap within their own area while Save retains its right-hand column. The prompt also fades, blurs, and scales away while Label is expanded, returning when it closes if no actions are configured. Save remains available when actions are configured. Clearing all actions reverses the transition unless Label remains expanded. The hidden Save control is disabled and excluded from keyboard focus and accessibility exposure. Reduced-motion preferences switch the text immediately. This replaces the separate inline save button; submission is disabled while busy or the question is blank. After a successful create response, action controls retreat and Save morphs to green “Saved!”. After a 650ms confirmation, the entire input silhouette moves into the persisted list row over 760ms, preserving its width and 16px radius (matching the action buttons) while transitioning to the saved card’s height, padding, and typography while its background transitions from light gray (`#f7f9fb`) to white and its border disappears. A temporary noninteractive field layer provides the visual continuity. The new card’s drag handle, individual action icons, active switch-icon button, and delete button stay hidden and inert during the field movement. After it arrives, those controls reveal in that order with a 420ms fade/slide/scale staggered by 110ms, becoming interactive after each reveal; reduced motion shows them immediately. Saved questions retain that field shape, with a drag handle before the question and a second row inside the white card containing action icons on the left and the active switch-icon button/delete button on the right. Saved question text uses 600 font weight. Collapsed cards have no side insets across breakpoints: the drag handle starts at the left edge, question text reserves only its 32px width, and the controls row starts 33px from the left to align its action badges with the question text (32px text padding plus its 1px border), with no right inset. The drag handle has 6px vertical and zero horizontal padding. Mobile action icons use tighter padding and gaps. The fresh empty input fades in after the field reaches its row; reduced-motion skips the delay and movement. Failed requests keep the draft/actions and show the existing error. Saved rows are placed above the composer; clicking an existing question expands that same white card into an editor, with question text, action buttons, optional label picker and Save on subsequent rows. Enable and delete buttons sit at the right of the action-button row without a visible Enabled label; their tooltips and accessible names identify them. On narrow screens, action choices wrap within the left area while the controls stay right. The expanded editor omits the visible “Question” and “When the answer is yes” headings; the textarea retains an accessible Question name, with no close-button row and 16px spacing before actions. Editing uses a single overlapping timeline with 620ms motion: shell expansion starts immediately, question motion at 60ms, actions in read/star/archive/label order at 140ms plus 55ms per action, and active/delete controls at 330/385ms. New choices and Save fade and slide in over 420ms, overlapping the moving controls. The question’s text layer interpolates its own position, width, weight and line height into the textarea independently of its container. Action, active, and delete controls animate the actual editor buttons and SVGs from their measured compact rectangles using one shared animation clock. SVG transforms compensate for the button transform at each sampled step so their screen position and size follow a continuous path, including asymmetric starting alignment. All transforms end at identity; there is no icon clone replacement at completion. Button-library CSS transitions are suspended during expansion. The form stays inert until the sequence completes and focus then moves to the question. Temporary layers are removed on completion or cancellation; reduced motion skips the sequence; Escape discards the draft. A successful edit save applies the returned persisted rule and animates the same card closed: editor-only choices, the label picker, and Save fade out over 180ms; active/delete controls and retained action icons move and shrink back with overlapping delays; the textarea text returns to the saved question row; the shell contracts; and the drag handle fades back in. The saved card uses the new text, actions, and active state immediately instead of waiting for a refresh. Focus returns to the question after motion, reduced motion collapses immediately, and failed saves keep the editor and draft open. Only one card edits at a time. The bold, light-gray (`#f3f4f7`) 32px hint “select one or more action” sits on the right and slides down first with the same 620ms animation, followed by the left-aligned action buttons at 140ms intervals. On exit the hint leaves last, before the editor unmounts; the row wraps on narrow screens, retaining the hint’s 32px size across breakpoints. Compact saved-card badges share the editor’s per-action pale backgrounds, colored fills, and contrasting internal details. Their SVGs resize continuously during the morph into editor buttons. Action buttons in both creation and expanded-card editing are colored icon-only squares with hover/focus tooltips, sharing selected fills and internal icon details: 56px desktop, 48px mobile. Label is purple, Star amber, Mark read blue, and Archive green; pale backgrounds remain in both states, with outlined icons when unselected and color-filled icons with action-colored outer strokes and contrasting pale internal details when selected, preserving their visual size. Archive keeps a pale lid with a colored outline; its handle, the mail fold, and the tag hole use pale details. Accessible names and HeroUI tooltips identify each action on hover and keyboard focus, with a 200ms hover delay. Saved rules sit above the composer. The signed-in shell fills the dynamic viewport height, with its footer at the bottom; when there are no rules, the composer is vertically centered in the available area between header and footer. Composer position changes caused by expanding or collapsing controls animate over 620ms with the action easing; a ResizeObserver measures layout changes and a reversible translation preserves the current visual position during rapid changes. Reduced-motion preferences skip this movement. Populated lists retain their top spacing, while the composer sits at the bottom of the content area above the footer. The questions page has no last-run status strip; History opens previous runs and Run now reopens an unfinished run. Main-page errors remain visible. Its grid reserves 128px below the desktop input and 176px below the mobile input for action controls, so revealing them does not lift the input; the larger mobile reservation accommodates wrapping. Longer lists or unusually tall controls grow the page naturally rather than overlapping content. The empty-list composer remains centered.

Settings uses the section and internal spacing detailed below, with a divider above account deletion. Gmail status and reconnect sit in one row, input/button rows align vertically, and Save preferences is right-aligned. Sign-out lives in the user menu.

The top bar groups matching ghost icon buttons on the right: History, Play to open Run now, and the user-icon button. History has a hover/focus tooltip and opens a 620px dialog of newest-first run summaries, with compact scope, date, status, counts and older/newer paging; each row opens the existing two-column run review. The history panel stacks row metadata on narrow screens. Its empty, loading and retry states use the same restrained text and surface styles. The user-icon dropdown shows Settings and Log out, without an account-email header, on both desktop and mobile.

The run setup dialog keeps its action row at the bottom of the panel. Cancel uses the secondary button treatment; Start run uses the filled primary accent treatment.

The signed-in footer includes a “How it works” text button beside Privacy. It opens a HeroUI modal with a short ordered guide, a labeled close control, and library-managed keyboard/focus behavior. Existing settings/run dialogs remain custom overlays.

The welcome description reads “Write a question. Choose an action. Mable cleans up your Gmail inbox.” It omits model names and processing granularity.

The welcome footer contains a GitHub icon with a Source link to `https://github.com/arminayat/mable`, Privacy, and “With love from Berlin” linked to `https://aayat.me`. Links wrap on narrow screens.

Automatic cleanup frequency and run scope use HeroUI Select and ListBox through `SelectField`; Gmail labels use HeroUI ComboBox and ListBox through `LabelPicker`. The shared popover sits above custom dialogs; label selection keeps its full-width mobile layout. HeroUI Button and Tooltip coexist with native buttons, textarea, checkbox, range, and inputs. Lucide icons indicate actions. Custom CSS sometimes targets button containers directly; inspect selectors before changing HeroUI variants. There is no complete tokenized spacing/typography system; many values are literal CSS.

Rows use a labeled drag handle with pointer capture for mouse/touch dragging and Up/Down keys for keyboard reordering, an editable question button, tooltip action icons, an `aria-pressed` enabled toggle, and labeled delete controls. Forms/errors include several explicit labels and `role="alert"`; focusable icon descriptions exist. Accessibility is partial: Settings lacks keyboard/focus lifecycle; the run and history dialogs provide Tab/Escape, initial focus and restoration, but browser accessibility acceptance is unverified. The key input has an accessible label.

The questions view has no Gmail connection indicator; connection status and reconnection remain in Settings. Run now is a header icon button and is hidden when there are no saved questions.
